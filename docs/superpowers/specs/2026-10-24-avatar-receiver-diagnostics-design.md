# Avatar receiver and observation diagnostics

User approved diagnostics implementation, cube build/deployment and a controlled one-warm-up plus ten-transition capture. No buffering, pacing, codec, protocol, runtime-limit or timeout changes are permitted.

## Measurement contract

Keep the existing ten-field frame_timing object unchanged. Append a separate observation_timing object on validated changed-token observations, recording actual callback entry, sampling end and decoding end on the performance clock, and their finite numeric/null deltas. Sampling includes canvas draw/readback; decoding includes stripe conversion/decoding. Existing now/epoch and listener order stay intact. Diagnostic failures never change observations or playback. Instrumentation must not fabricate native timestamps.

A small receiverStats module owns one asynchronous getStats collector per connection generation. Read both inbound audio and video from one RTCPeerConnection report, allowlisting primitive numerical counters and kind/report identity. Derive interval averages from nondecreasing cumulative counters and strictly increasing report timestamps, matching report id, kind and SSRC. Actual/target/minimum jitter delay = 1000 * delta delay / delta emitted count; decoder mean =1000 * delta totalDecodeTime / delta framesDecoded. Missing fields, zero denominator, reset, nonfinite values and identity changes produce null rather than zero or stale deltas. Retain only last successful snapshots of currently present inbound reports, not application payloads or full RTCStats reports. Report loss, NACK, PLI, retransmission where available, freezes, audio concealment and audio sample corrections as raw counters/deltas with explicit units. Negative packetsLost is valid and must not be silently clamped; counters requiring monotonicity must reset their interval on decrease.

Collect without timers: request a baseline when playback becomes ready, then asynchronously on changed-token observations after playback listeners. No await/getStats call in the synchronous canvas/stripe critical path: schedule collection in a promise continuation. Preserve request correlation (turn, RTP/native timestamp and performance origin), and label actual stats timestamps: snapshots are interval aggregates, not same-frame measurements. Do not queue requests behind a stuck getStats call: if a request overlaps an existing collection, emit an explicit unavailable/busy diagnostic without altering playback or inventing a timeout. This is diagnostic serialization, not a media queue or runtime limit. Stop/dispose fences late results, prevents further sampling and clears baseline state. No new retries, deadlines, polling or unbounded request queue.

No SDP, candidates, IP addresses, auth, application contents, user queries or raw report serialization in diagnostics. Failure logging uses fixed reasons, not exception strings. All logger failures are isolated. Unsupported getStats/fields must not break existing lightweight test doubles or production media.

## Verification and rollout

TDD each new behavior, at most three actual cases per process, no timeout changes. Independent spec review then quality review, parent fresh bounded regression verification and SDK build. Preserve unrelated dirty files and staged index. Never package unrelated uncommitted SDK changes: export exact committed revision. Build SDK and Avatar on ARM64 cube with own locked SDK deps and official Avatar build, immutable tarball/new coherent release version/locks, strict native verification. Preserve original app/profile and rollback artifact; verify actual empty dpkg -V output and ASAR identity.

Coordinate current runtime owners before restart/capture. Freeze versions; one warm-up followed by ten warmed transitions in a fixed non-destructive scenario through the real installed Avatar/client path. Keep outliers, deduplicate exact log copies, partition by renderer/session generation, record supported and missing fields, counter intervals and callback sampling/decode stages. No unauthorised microphone use, auth/history reset, destructive tool use or other-component restarts. If capture entrypoint, deployment ownership or integrity cannot be established safely, stop that phase and report evidence/blocker; do not substitute a direct classifier/provider call or claim audible/visual acceptance from logs alone.
