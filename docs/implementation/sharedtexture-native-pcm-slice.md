# Native PCM custody source checkpoint

`PcmCustody` owns accepted eligible PCM blocks plus immutable attachment/turn/sequence/sample provenance, intrusive active/completion/pending/retired chains and lifetime cancellation marks. Caller serializes nonRT APIs and supplies a synchronous actual processing-loop barrier and RT-safe notification callback. The core itself does not create a PipeWire stream or processing thread. Barrier commands mutate/take chains in constant time on RT; prune/reclaim/metadata allocation happens off RT. Data copies obey actual capacity rounded to whole S16LE frames and requested frame count; no invented padding, media reserve/pool/ceiling.

Stop captures exact target+turn, suspends/takes chain at barrier, prunes only cancelled turns and retains partial offsets. B already handed off, queued or arriving while suspended remains unchanged. Late A is cancelled through generation lifetime. Conservative per-scope handoff history forbids whole-stream flush if B/unknown is potentially retained; actual reset can be recorded only while suspended with no protected scopes. This core only computes permission; it never flushes/recalls device PCM. Completion means bytes copied into caller-provided storage, not acoustic/device use. Whole EOS fences admissions and exposes software handoff readiness only; no normal voice completion, ACK or actual PipeWire drain.

Close fences admissions then joins the processing barrier before reclaiming. The processing-loop owner must outlive explicit close; destructor cannot silently retire abandoned live RT ownership. Notification only signals completion availability; caller collects through barrier offRT, no completion polling. No mutable current-turn lookup or cancellation scanning in RT.
