# Native PCM custody / RT processing slice — bounded plan

Next dependency after72fc743: implement the attachment-owned PCM handoff/cancellation core before real PipeWire stream creation. This is part of audio ownership, not claimed PipeWire/native READY or public host completion. Real pw_stream negotiation, RT loop-invoke adapter, callback event notifier, drain/PAUSED/flush and NAPI asynchronous cleanup remain next integration slice. No device operations here.

Owned PCM blocks allocated off RT from accepted eligible frame bytes with immutable generation/turn/sequence/sample metadata. One serialized nonRT owner supplies a synchronous processing-loop barrier function executed off the libuv receive loop; future production binding uses the stream's actual pw_loop_invoke, not thread-loop-lock alone. Test harness executes barriers and process callbacks on a dedicated deterministic processing thread. No new product thread/media queue/pool/capacity/deadline introduced by this core.

RT owns an intrusive head/tail/current offset, gets O(1) chains through the processing-loop barrier, copies only complete available S16LE frames within actual writable capacity and requested frame count. RT never allocates/frees/calls JS/locks or scans cancellation records. Completed blocks remain on an intrusive RT completion chain with callback notification; collect obtains that chain in O(1) at the same processing-loop barrier, then reclaims/constructs ordered completion records off RT. Empty PCM completed off RT. Notification contract is RT-safe C function pointer (future PipeWire loop event), not arbitrary std::function/JS.

Targeted stop captures exact supplied turn, retains mark through generation lifetime. Begin-stop barrier suspends RT and transfers whole current chain/offset in constant time. Prune only A off RT, retain partially copied B and metadata, retain arriving B above handoff while suspended; later A rejected by mark. Resume returns chain in constant time, preserving bytes/offsets. Conservative handed scope flags retained until actual whole-stream flush/drain: unknown or any un-cancelled scope forbids global flush. Core reports permission only while suspended; actual PipeWire owner must deactivate/observe PAUSED/flush(false)/resume and only report completed reset after actual flush. No selective recall claim. EOS only closes new admission and allows explicit software-handoff-ready observation after all accepted bytes copied/cancelled; no turn-boundary drain, no device/acoustic/normal voice completion certificate. Close fences then invokes real processing barrier and joins block ownership; no fake PipeWire retirement or ACK.

API-visible tests: exact bytes across partial output and requested sizes, immutable metadata/once completion, empty PCM, FIFO/order, cancelled-A-late admission, B partially handed/queued/arriving during suspended stop, unknown/mixed flush prohibition, A-only flush possibility, EOS not before handoff, repeated close/actual processing barrier with in-flight callback, zero RT allocation/free through link-time allocation instrumentation. Core remains unattached to LocalConnection until real output owner exists, so no fake readiness. C++17 Werror, existing libuv/native/goldens/portable named batches.
